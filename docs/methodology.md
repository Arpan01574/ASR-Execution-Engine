# ASR Engine v3 — Test Methodology

This document explicitly defines the test methodology, execution assumptions, and statistical thresholds used by the canonical Python backtester to ensure robust, non-deceptive results.

## 1. No-Lookahead Guarantees

To ensure event-time correctness and prevent lookahead bias (peeking into the future), the following guarantees are hardcoded into the Python engine:

- **Confirmed Bars Only:** The engine only evaluates conditions using data from *completed* bars. Intrabar data (ticks) is not used to change state mid-bar.
- **Pivot Confirmation Delay:** A pivot high/low at index `i` is not mathematically known until `i + pivR`. The backtester strictly enforces this delay. A zone generated by a pivot at index `i` becomes `CREATED` at `i + pivR`, not at `i`.
- **HTF Confluence:** When checking Higher Timeframe (HTF) data (e.g., 4H trend while trading 15m), the backtester only uses the most recently *closed* HTF bar relative to the current LTF bar's timestamp. It does not interpolate or peek at the closing value of the currently developing HTF bar.

## 2. Same-Bar Execution Model

When multiple price levels (Entry, Stop Loss, TP1, TP2) are touched within the exact same candle, it is impossible to know the exact sequence of intrabar ticks using only OHLC data. 

To prevent optimistic bias, the ASR Engine employs a **Conservative Fill-Order Assumption** for intrabar events.

### Entry Bar Assumptions
If an entry signal triggers at the Open or Close of a bar, and the same bar touches both the Stop Loss and a Take Profit level:
- **Assumption:** The Stop Loss was hit *first*.
- **Result:** The trade is recorded as a full 1R loss.

### Open Position Assumptions (Post-Entry)
For an open position, if a single bar touches multiple levels, the evaluation order is strictly as follows:

1.  **Check Stop Loss (SL):**
    *   If `Low <= SL` (for Longs) or `High >= SL` (for Shorts), the trade is immediately closed as a loss (or BE if the stop was moved). No TPs are credited.
2.  **Check Take Profit 1 (TP1):**
    *   If SL was *not* hit, we check TP1.
    *   If `High >= TP1` (for Longs) or `Low <= TP1` (for Shorts), we record a partial realization (e.g., 33% of position at 1.5R).
    *   *Crucial Step:* The stop loss is immediately moved to Breakeven (Entry Price).
3.  **Check Breakeven (Same-Bar Trailing):**
    *   If TP1 was hit in this bar, we now re-evaluate the *new* Breakeven stop against the *current* bar's extremes.
    *   If the current bar's Low (Longs) or High (Shorts) would have hit the Entry Price, the remainder of the position is closed at Breakeven.
4.  **Check Take Profit 2 (TP2):**
    *   If the remainder survived the BE check, we finally check TP2.
    *   If reached, the remainder is closed at TP2.

**Why this matters:** If a bar opens at Entry, spikes up to TP1, and then crashes down to the Stop Loss, an optimistic backtester might record a TP1 win + BE. Our conservative backtester records it as a full SL loss (Rule 1). If the bar opened, hit TP1, and came back to Entry, it records the TP1 partial win, and the remainder is stopped at BE (Rule 3).

## 3. Statistical Reliability

A high win rate on 20 trades is noise. To ensure robustness, the following statistical reliability thresholds are applied during the Verdict phase:

-   **Minimum Sample Size:** `300 trades`. Any backtest or subgroup (e.g., specific setup type) with fewer than 300 trades is flagged with a warning (⚠️) and cannot receive a definitive "PASS" verdict.
-   **Robust Expectancy:** Minimum `0.05 R` per trade over the entire sample.
-   **Maximum Drawdown:** Maximum acceptable drawdown is `25 R`.
-   **Minimum Profit Factor:** `1.15` (Gross Profit / Gross Loss).

## 4. Control Comparisons

To isolate the actual edge of the ASR logic from market drift or base volatility, the engine compares canonical results against a **Random-Entry Control**:

1.  Generates random entry timestamps matching the exact frequency of ASR signals.
2.  Applies the exact same exit model (SL, TP1, TP2, BE trail, Time Stop).
3.  Simulates 50-100 random runs.
4.  Calculates the baseline "Random Expectancy".
5.  The true edge is defined as: `ASR Expectancy - Random Expectancy`.

## 5. Walk-Forward Stability

Optimization is never performed on the full dataset (In-Sample).

1.  **Train (60%):** A simple grid search finds parameters that maximize expectancy.
2.  **Validation (20%):** The best parameters are run against unseen validation data.
3.  **Test (20%):** The final out-of-sample (OOS) performance is logged.

**OOS Stability Ratio:** Defined as `Test Expectancy / Validation Expectancy`. A ratio below `0.70` (70%) indicates severe overfitting, and the strategy is rejected.
